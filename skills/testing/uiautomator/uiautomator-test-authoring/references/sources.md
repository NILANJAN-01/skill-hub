## Where the guide and the 2.4.1 API disagree

The guide was written during the 2.4 alphas. These skills follow the 2.4.1 reference and source:

| Guide shows | 2.4.1 actually has |
|---|---|
| `androidTestImplementation("...uiautomator:2.4.0-alpha05")` | `2.4.1` (stable) |
| `clearAppData("com.example.targetapp")` | `clearAppData()`: no argument, clears the instrumentation target app |
| `startIntent(myIntent)` | `startActivityIntent(intent)` |
| `import androidx.test.uiautomator.PermissionDialog` | `androidx.test.uiautomator.watcher.PermissionDialog` |
| `uiautomator { ... }` (screenshot sample) | `uiAutomator { ... }` |
| `onElement { viewIdResourceName == "my_button_id" }` | Works only for Compose test tags; for Views `viewIdResourceName` is `"pkg:id/my_button_id"` (the library's own `PermissionDialog` compares full ids). Use `simpleViewResourceName()` for the short form |
| `textAsString == "..."` (some KDoc samples) | `textAsString()` is a function |

## Verified while building these skills

- The Java examples in `java-api.md` and Java code generated by `uia_scaffold.py` were compiled with `javac` against `uiautomator-2.4.1`, `androidx.test.ext:junit:1.3.0`, `androidx.test:core:1.7.0`, `monitor:1.8.0` and `android-36` (no errors, no deprecation warnings). Kotlin output was not compiled.
- `MacrobenchmarkScope` in `androidx.benchmark:benchmark-macro:1.5.0` extends `UiAutomatorTestScope` and depends on uiautomator 2.4.0.
- Watchers: the DSL's element search calls `UiDevice.runWatchers()` on every poll; `UiDevice.findObject(BySelector)` does not run watchers.
- `uiautomator` depends on `uiautomator-shell` as an implementation dependency, so `ShellServer` needs its own `androidTestImplementation`.
