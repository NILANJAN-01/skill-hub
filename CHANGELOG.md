# Changelog

Notable changes to skill-hub. Newest first. Skills are listed by name; see `git log` for detail.

## Unreleased

- Tooling: hooks in `tools/hub.py`. `hook post-edit` rebuilds the generated files after an edit to any of their sources, and is silent unless the build fails or a generated file was edited by hand. `hook stop` runs `check --changed` when an agent is about to finish and, if it fails, blocks once per failing state with the short report (at most 3 times a session; states that passed are not rechecked). `hook pre-commit` verifies without writing. `setup-hooks` installs the git pre-commit hook (never replacing a foreign one) and merges the agent hooks into `.claude/settings.json`, keeping other settings; it is a dry run unless `--yes`, and `--remove` undoes it. `HUB_HOOKS=off` disables all of them.
- Updated: `contribute-skill` uses `hub.py new-skill` and `hub.py check --changed`, keeps the manual steps for older checkouts, and covers the new placeholder errors.
- Tooling: `tools/hub.py`, one command per repository chore with short output. `check` rebuilds the generated files and then runs everything CI runs in parallel (about 14 s instead of about 60 s one after another), printing one line per step group, the output of failed steps only and the command to rerun each; `--changed [REF]` runs only the tests affected by changes. `new-skill` copies `template/`, writes the frontmatter, registers the skill in `marketplace.json` (also creating a new plugin and its `CATEGORY_TITLES` entry) and `examples/prompts.json`, and rebuilds. `validate_skills.py` now rejects leftover `TODO:` placeholders and template text.
- Added: `lint-checker` (new `code-quality-tools` category): lint a project in any language. `lint_check.py` detects languages and the configured or installed linters (ruff, ESLint, Biome, golangci-lint, clippy, RuboCop, ShellCheck and more), runs them in one report with a dry-run-first `--fix`, lints only changed files with `--changed`, and has built-in checks that need no tools (conflict markers, Python/JSON/TOML syntax, leftover debug code, whitespace). Java and Kotlin are linted through the Gradle or Maven build's Checkstyle, PMD, SpotBugs, ktlint, kotlinter, detekt, Spotless and Android Lint tasks, run with the project's wrapper.
- Added: software design skill set (new `software-design-tools` category, `skills/development/software-design`), based on the ideas in *A Philosophy of Software Design* (John Ousterhout) and written in original words: `software-design-guardrails` (always-on design rules; `install_guardrails.py` writes them into a project's agent instruction files, copies the checker into the project and adds a pre-commit hook, as a dry run unless `--yes`; `design_check.py` flags red flags such as pass-through methods and variables, shallow one-use functions, overexposed parameter lists, swallowed and repeated error handlers, duplicated code, comments that repeat code, missing or contaminated interface comments, vague names, generic containers and kludge markers, for Python via `ast` and for C-family languages heuristically, on whole trees or only changed lines (`--diff`, `--staged`), with baselines, inline ignores and JSON output), `deep-modules` (interfaces, information hiding, layers, splitting and merging), `error-handling-design` (define errors out of existence, mask, aggregate, crash), `obvious-code` (comments, names, consistency) and `design-it-twice` (compare designs before coding; `design_note.py` scaffolds and checks the design note; strategic programming; performance).
- Added: context management skill set (new `context-management-tools` category): `context-handoff` (when to checkpoint, compact or restart a long agent session; `handoff.py draft` pre-fills a handoff note from git state and `check` flags missing sections, phrases that rely on lost history, relative dates, missing files and secrets in notes and sub-agent briefs), `context-memory` (durable one-fact-per-file agent memory with an index; `memory_lint.py` lints a memory folder for unindexed or dead entries, duplicates, missing reasons, stale file references, relative dates and secrets, and builds the index), `context-window-budget` (context budgets for LLM apps and agent loops; `context_budget.py` plans a window, analyses where a transcript's tokens go and trims it by truncating or clearing old tool results and dropping whole old turns without splitting tool-call pairs). The bundle also includes `context-engineering`.
- Added: `rest-api-testing` (new `api-testing-tools` category): REST API testing for web applications in any field. It plans cases from an OpenAPI spec (`api_check.py plan`), lints suites for typos, literal secrets, order bugs and unsafe retries (`lint`), and runs JSON suites (`run`) with variables and chaining, cookies, schema/contract checks, retries only for idempotent requests, polling instead of sleeps, `allowed_hosts`, `--read-only`, masked secrets and JUnit/Markdown/JSON reports. References cover test design and the OWASP API Top 10, REST Assured, pytest, Postman/Newman, Karate, Playwright and SuperTest, and checklists for banking, healthcare, e-commerce, insurance, telecom, travel, logistics, government, SaaS and media.
- Added: JUnit skill set (new `junit-tools` category, Java and Kotlin, JUnit 6.1.3): `junit-test-authoring` (setup check and a test-class generator for Java and Kotlin sources), `junit-migration` (audit for JUnit 3/4/5 code, removed JUnit 6 APIs, tests that never run and weak tests, with migration guides), `junit-run-reports` (Gradle/Maven/ConsoleLauncher commands and a summary of JUnit XML and Open Test Reporting results with causes, flaky and slow tests). The bundle also includes `kotlin-unit-test`.
- Added: UI Automator skill set (new `uiautomator-tools` category, Kotlin and Java, androidx.test.uiautomator 2.4.1): `uiautomator-test-authoring` (setup check and generator for tests, page objects, Macrobenchmarks and Baseline Profile generators), `uiautomator-migration` (audit of legacy and flaky code with a migration map), `uiautomator-run-debug` (runs tests with Gradle or `am instrument` and explains failures from raw output or JUnit XML). The bundle also includes `android-uiautomator-locators`.
- Added: `user-guide.html`, the master user guide: quick start, concepts, the full skill catalog with scripts and example prompts, installer reference, supported agents, MCP server tools and presets, maintainer tasks and this changelog. It is generated by `tools/build_catalog.py` from the skills, `install.py`, the MCP server and the rules, so it updates with every change (and `--check` fails if it is stale).
- Added: Robot Framework skill set (new `robotframework-tools` category, up to RF 7.5): `robotframework-test-authoring`, `robotframework-libraries`, `robotframework-results`, `robotframework-ci`, each with a script; result-analysis fixtures were produced by Robot Framework 7.5.1.
- Added: Playwright skill set (new `playwright-tools` category, up to Playwright 1.65): `playwright-test-authoring`, `playwright-debugging`, `playwright-ci`, `playwright-mcp-browser`, `playwright-upgrade`, each with a script except the MCP browser skill.
- Added: AI agent skill set (new `ai-agent-tools` category): `mcp-server-builder`, `agent-tool-design`, `llm-evals`, `rag-pipeline`, each with a script.
- Installer: `--setup` installs every skill and registers the skill-hub MCP server for every detected agent in one command; `--doctor` checks skills and MCP setup per agent; `--uninstall` removes everything it set up. The MCP server runs from a hub copy in `~/.skill-hub/hub`.
- Installer: `--add-mcp`, `--remove-mcp`, `--list-mcp`, `--mcp-command`, `--mcp-arg`, `--mcp-env` and `--mcp-test` manage any MCP server across all agents (presets for filesystem, memory, fetch, git, time, playwright, github and more). Config files are merged, only the named entry changes, and the first edit keeps a `.skillhub-backup`.
- Installer: per-agent MCP config locations (JSON and Codex TOML) in `AGENTS`, from vendor docs; options are grouped in `--help`.
- `skill-router`: routing hints for the new skills.

## 1.3.0 - 2026-11-16

- Changed: skills moved from `skills/<name>/` to `skills/<area>/<group>/<name>/`, with five areas (`testing`, `development`, `design`, `generic`, `external-tools`) and group subfolders. Skill names, plugin names and install commands are unchanged. `catalog.json` gains `area` and `group` per skill and an `areas` list, and each skill's `path` is its new folder. The installer, validator, catalog builder, both MCP servers, `skill-router` and `skill-orchestrator` find skills at the new depth; the installer still reads older flat releases. The validator rejects skills outside the layout and duplicate names.

- Added: `skill-hub-mcp/`, a new MCP server kept beside `mcp-server/`. It searches (BM25), routes multi-part requests to skills, reads playbooks, detects agents, lists installed skills, and plans installs, updates and removals. With `--allow-install` it can apply a plan the user agreed to, through a one-time token; without it the server is read-only.
- `skill-router`: word forms now share a stem, so "rebase" finds `git-rebasing`; routing hints added for `git-rebasing`, `git-rewriting-history`, `git-undoing-things` and `git-stashing-and-cleaning`.
- `template/`: added `references/details.md`, so the link in the template's `SKILL.md` resolves.
- Added: `context-engineering` (in `ai-efficiency-tools`): one central context file, thin pointers for each tool, layered loading, a token budget and handoff notes, with a script that finds duplicated or drifting instruction files and creates the pointers.
- Added: `ai-token-saver` (new `ai-efficiency-tools` category): audits a project for context waste and lists habits that cut token use and cost.
- Added: `adb-tool`, `adb-connect`, `adb-device-control`, `adb-debug` (new `adb-tools` category).
- Added: `gradle-android` (new `gradle-tools` category).
- Added: `install.bat`, a one-shot Windows installer with precondition checks. It now honours `SKILLHUB_REF` instead of always reading `main`.
- Installer: update detection compares every file of a skill, not only `SKILL.md`, so a change to a bundled script or reference is now reported and `--update` refreshes it. Line endings are ignored.
- Installer: records what it installs in `.skill-hub.json` in each skills folder (skill, hub version, repository); new `--installed` lists the hub skills an agent has, their version and whether they still match the hub.
- Installer: a release download (`--ref v1.3.0`, or the new `SKILLHUB_REF`) uses the release archive and checks it against the release's `SHA256SUMS`; a mismatch stops the install.
- Installer: unit tests in `tools/test_install.py`, run by CI and the release workflow.
- Docs: the `--plugin` table in `GUIDE.md` is generated from the marketplace (it listed 14 of 22 plugins); update, remove and pinning steps corrected; marketplace description is agent-neutral.
- MCP server: removed the `uvx skillhub-mcp` instruction. That PyPI name belongs to an unrelated project; this server has not been published.
- Repo: rules moved into `rule/`; `code-reviewer` agent for skill review.
- Added: `skill-router` (in `hub-tools`): front door for any request. Splits it into parts, grades each basic or advanced, checks the basics are given (file, link, device, tools), and picks the installed skills to load, with editable routing hints and a hand-off to `skill-orchestrator` for multi-skill jobs.

- `skill-orchestrator`: hand-off briefings for inter-skill communication. `run done` records `--fact key=value` and `--question` beside the note and outputs, and the new `run handoff DIR [N]` prints one briefing of everything earlier steps passed on.

## 1.2.0 - 2026-11-14

- Added: `python-tutor` (new `learning-tools` category): explains any `.py` file from beginner to advanced and generates self-contained study-notes HTML (walkthrough, ~75 concepts by level, gotchas, interview Q&A, fundamentals checklist). The file is parsed, never run.
- `python-tutor`: Functionality section (call tree, inputs, outputs, side effects, public API, docstring examples), `--only` to explain selected functions or classes, loose mode for Python 2 files and syntax errors, warnings about suspicious explanations, and notes that follow moved code.

## 1.1.0 - 2026-11-14

- Added: `repo-architecture` (in `repo-tools`): scans a repository and drafts `ARCHITECTURE.md` (Mermaid) and a self-contained `architecture.html` (layered SVG), then guides the reader to describe components and flows.
- Added: `powershell-commands` (new `shell-tools` category): PowerShell playbook for agents with a bash-to-PowerShell map and references for files, text and data, processes, network, dev tools, scripting and troubleshooting.

## 1.0.0 - 2026-11-14

- Release: tagged releases (`v*`) now publish a GitHub Release with a version-pinned `install.py`, `catalog.json`, one zip per skill, a full-repo zip and `SHA256SUMS`. The version lives in `.claude-plugin/marketplace.json` and is stamped into `catalog.json`.
- Installer: `--ref` accepts release tags, new `--repo owner/name` (or `SKILLHUB_REPO`) so forks can distribute their own copy. The MCP server honours `SKILLHUB_REPO` too.
- MCP server: `publish-mcp.yml` publishes `skillhub-mcp` to PyPI on `mcp-v*` tags; without a clone it falls back to reading GitHub.
- Repo health: `SECURITY.md`, `CODE_OF_CONDUCT.md`, issue templates; README licence section explains the CC BY-NC-SA `git-*` skills.
- Added: `skill-orchestrator` (in `hub-tools`): finds installed skills, plans multi-skill workflows, checks requirements and tracks hand-offs between steps.
- Added: `professional-writing` (new `writing-tools` category): blog posts, CVs, cover letters and technical docs, with templates and a checker script.
- Added: `repo-learnings` (new `repo-tools` category).
- Added: `gitlab-ci-pipeline-authoring`, `gitlab-ci-debugging`, `gitlab-ci-optimization` (new `gitlab-ci-tools` category).
- Added: `android-logcat-analyzer`, `kotlin-unit-test` (new `testing-tools` category).
- Installer: `--update` (refresh installed skills) and `--remove` (uninstall selected skills).
- README: category table, plugin list and skill counts are now generated; "Start here" section; MIT `LICENSE`.
- CI: unit tests of every skill that has tests now run automatically.
