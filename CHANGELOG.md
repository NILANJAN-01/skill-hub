# Changelog

Notable changes to skill-hub. Newest first. Skills are listed by name; see `git log` for detail.

## Unreleased

- New skills from *The Prompt Report* (Schulhoff et al., 2024, CC BY 4.0), a survey of 1,565 prompting papers. Each skill has a standard-library script and tests:
  - `prompt-engineering`: choose and apply prompting techniques with a decision guide (zero-shot, few-shot, chain-of-thought, decomposition, self-consistency, self-critique). Its script, `prompt_lint.py`, checks a prompt or chat-message file for the failure modes the survey documents: unbalanced or grouped exemplar labels, mixed exemplar formats, no answer space, reasoning without a final-answer marker, the user's opinion or a false presupposition (sycophancy), undelimited input and personal data. It reported nothing on well-formed prompts, including the paper's own.
  - `llm-classification-prompts`: the paper's case-study loop for labeling prompts. `prompt_bench.py` builds few-shot variants (balanced, random or similar exemplars, several orders), runs them through any model command (resumable, in parallel), compares answer extractors, and scores precision, recall, F1 and the unparsed rate. It also does self-consistency and order ensembling, shows which items a change fixed or broke, and automates AutoDiCoT reasoning exemplars.
  - `llm-app-security`: `llm_sec.py` finds model output that reaches `eval`, a shell, SQL, HTML or Markdown, system prompts built from user input, and secrets or "confidential" rules in prompts. It catches hallucinated imports in generated code, offline or by looking them up on PyPI or npm, and flags packages first published in the last 90 days as possibly squatted. It also probes a prompt with 12 injection and prompt-leak attacks, using a canary.
- The **Security** and **AI agents** categories now list these skills; `llm-evals` and `secrets-dependency-audit` point to them.
- New skill: `secrets-dependency-audit` in a new **Security: secrets & dependencies** category. Its standard-library script finds committed secrets: private keys, cloud and API tokens from 15 providers, passwords in URLs, and secret-named variables holding random values (placeholders are ignored). It scans the working tree, only the staged lines (`--staged`, with an optional pre-commit hook), or git history (`--history`). It never prints a full secret. A second command, `deps`, flags risky dependency setups: unpinned or wildcard versions, missing lock files, http registries, `--extra-index-url`, unpinned Docker images and GitHub Actions, and `curl | sh`. Findings can be accepted with a baseline or `audit:ignore`. Run over this repository, it reported only the hub's own test fixtures, in about 3 seconds.
- Skills cost fewer tokens when used. The 60 `git-*` skills now load a short SKILL.md (median about 470 tokens instead of 2,200): the safety rules, the commands, the fixes and related skills. The full playbook moved unchanged to each skill's `references/playbook.md`, read only when a step needs it; no line was lost. Agents already know Git well, so the book text mostly repeated what they knew. Across all 121 skills, the SKILL.md text read on use fell from about 237,000 to 131,000 tokens (median 1,741 to 785).
- Updated: `skillforge` writes skills in the same two parts (a short SKILL.md and `references/playbook.md`), so regenerating them keeps them small.
- Updated: `android-logcat-analyzer`: the report prints each message once (it repeated a crash message up to six times), and the skill says to read a log under about 150 lines directly. Measured on growing inputs, the analysis scripts cut what the agent reads by 93-100% (a 60,000-token log becomes a 4,000-token report; a Robot Framework run of any size, 260 tokens).
- Token budgets: `validate_skills.py` (and so `hub.py check` and CI) now fails a skill whose description is over about 130 tokens (every session reads it) or whose SKILL.md body is over about 5,000 tokens (every use reads it); long material belongs in `references/`. All 121 skills fit. Updated: `git-submodules` (5,800 to 4,700 tokens: a duplicated procedure removed, "Submodule Tips" moved to its references).
- User guide: a search across the whole guide (press `/` or Ctrl+K): every section, heading, skill, script, installer option, MCP entry and FAQ answer, grouped, highlighted and keyboard-driven, and each result opens the right place. Also: an "I want to…" panel of common tasks, subsections and shareable links for every heading in the contents, a "Requirements by skill" table, FAQ entries on packages, tokens and finding things, search on phones, back-to-top, print styles and a skip link.
- Skills with scripts no longer need any Python package (`pip install`): each now runs on the Python 3.8+ standard library, and tests run with site-packages disabled (`python -S`). Where a job truly needs a codec or a model, the script calls a standalone program instead of a package.
  - `rest-api-testing`: YAML OpenAPI specs (and YAML suites) are read by the bundled `yaml_lite.py` instead of PyYAML. It matched PyYAML exactly on 163 real files, including GitHub's 11 MB and Stripe's 6.6 MB specs, and is about 2.5x faster than PyYAML's C loader.
  - `skillforge`: `pdf_lite.py` replaces PyMuPDF and `nlp_lite.py` replaces scikit-learn, numpy and yake; `requirements.txt` is gone. On *Pro Git* the plan is identical (the same 60 skills from the same 383 sections) and the run takes 12 s instead of 31 s. TF-IDF and PageRank match scikit-learn and numpy to 6 decimals. It also fixes words being glued together when a PDF draws spaces in their own font, skips text hidden by clipping paths, and keeps ligatures and spaces that PyMuPDF dropped. `--engine pymupdf` still uses PyMuPDF when it is installed.
  - `image-inspector`: pure-Python JPEG (baseline and progressive), GIF, TIFF, PNM and EXIF decoders whose pixels are bit-exact with Pillow (verified with fixture hashes). `--find`, `--compare` and sharpness no longer need OpenCV: scores use OpenCV's formulas, and a phone screenshot search takes 1-2 s. OCR calls the Tesseract program directly instead of pytesseract. Pillow is still used, when installed, for speed and for WebP/HEIF; ffmpeg can decode those too.
  - `video-inspector`: frames are decoded by the ffmpeg program and analysed in pure Python with OpenCV's HSV, histogram, Bhattacharyya, gray and Laplacian formulas. On a 720p test video the scenes, black and frozen sections and tracked colours match the OpenCV version, in half the time. OpenCV is used only when ffmpeg is missing. Frame sharpness is now measured at 320 px (was 512 px), so its values are lower than before.
  - `yt-lecture-overview`: the audio stage decodes with the ffmpeg program when PyAV is missing, the loudness analysis is pure Python (no numpy), slides can be captured with ffmpeg, and a new `whisper-cpp` engine turns speech into text with the whisper.cpp program, so the whole pipeline can run without pip.
  - CI installs ffmpeg for the video tests; Pillow and OpenCV stay only for tests that compare results against them.
- Installer (internal): the MCP server entry, the `skill-dispatcher` hook and the `token-optimizer` hooks are planned, shown and written by one `ConfigEntry` module in `tools/install.py`, with an adapter per entry, instead of three copies of the same code. Visible effects: the plan and apply lines use the same wording for all three; removing a hook no longer needs its skill folder to exist; re-adding a hook also cleans up a copy left under a different event; and the `token-optimizer` hooks say "add" or "update" instead of "set". `tools/hub.py setup-hooks` merges its hooks with the installer's code.
- Installer: the guided menu (`python install.py` with no options) now covers install, update and remove for single skills and for MCP servers. New choices: **Install or update skills you choose** (everything, plugins, only the installed skills with an update, or single skills found by a word in their name; each is marked `[x]` installed, `[!]` update available or `[ ]` not installed), **Update or remove installed skills** (pick from what is installed, then update or remove; removing `skill-dispatcher`, `skill-router` or `token-optimizer` also removes their hooks), and **Add or remove MCP servers** (the skill-hub server, every preset and the servers already configured, each with how many agents have it; presets that need folders ask for them). It asks "Where?" before the skills, so their states match the folders it will change, and asks again after an unknown menu number. An update never installs new copies; it only replaces copies that differ from the hub.
- Docs: `CLAUDE.md` is a thin pointer to `AGENTS.md`; commands and architecture moved to `ARCHITECTURE.md`, read on demand, and the skill-router rule moved to `AGENTS.md`.
- Updated: `lint-checker`.
  - **Security (Windows):** file names containing characters `cmd.exe` acts on (`& | < > ^ % ! " ( )`) are no longer passed to `.cmd`/`.bat` tools such as npm's `node_modules/.bin` shims, where a name like `a&calc&.md` could run a command. They are listed as not linted, and the run reports INCOMPLETE (exit 3).
  - **Fewer false languages and alarms:** Gradle's `*.gradle.kts` build scripts no longer make a Java project count as Kotlin. `.vue`, `.svelte` and `.astro` components count as JavaScript, so ESLint or Biome runs on them. The `mixed-indent` check ignores the bodies of block comments and Python docstrings.
  - **Faster:** build files are scanned once per run instead of five times.
  - The description mentions coding standards and static analysis, and a `compatibility` field states the requirements.
- Installer: a professional finish for `--setup`, `--uninstall` and the rest.
  - **Clear source and exit codes.** The first line says which version is installed and where from (local clone, a checksum-verified release, or `main`, which is not verified). Every run ends with a summary, and items left to do by hand (a config file it could not parse) are listed as "need your attention". Exit codes are 0 done, 1 error, 2 bad options, 3 partly done, 4 cancelled (in `--help`).
  - **Shorter output.** One line per folder instead of one per skill, so a setup prints about 25 lines instead of 270; `--verbose` lists every skill. New `--version`.
  - **Readable errors.** A failed download (404, offline, proxy, TLS certificate) prints one actionable message instead of a Python traceback. A mistyped agent, plugin or skill suggests the closest name ("Did you mean claude-code?") without the full usage text.
  - **Nothing left behind.** A download run deletes its temp copy of the hub, which was left in the temp folder before. `--uninstall` deletes the `.skillhub-backup` files once a file is back to its original content (and lists any it keeps), and deletes config files that setup created when they end up empty. Merged JSON files keep their indentation.
  - **License note.** The plan says when it includes the 61 non-commercial (CC BY-NC-SA 3.0) `git-*` skills and how to choose plugins instead.
  - The summary says which Python runs the MCP server, so an upgrade that breaks it is easy to fix (`--setup` again).
  - The skill-hub MCP server also installs the skills a skill requires, and shows installer messages for exit code 2.
- Docs and `install.bat`: the one-line install commands use the installer from the latest release (it installs that release and verifies its checksum); `main` is documented as the latest development version. `install.bat` downloads the release installer unless `SKILLHUB_REF` is set and enables TLS 1.2 for older Windows PowerShell.
- Tooling: distribution checks. `template/SKILL.md` is now `template/SKILL.md.tmpl`, because `npx skills` installed it as a placeholder skill named `template-skill`; `hub.py new-skill` renames it in the copy, and `validate_skills.py` rejects any `SKILL.md` outside `skills/<area>/<group>/<name>/`. New `metadata.requires` frontmatter field: `install.py` also installs the skills a skill needs (announced as `+ <name> (needed by ...)`; `--remove` leaves them in place), and the validator checks that they exist and that every plugin listing the skill lists them too. CI and `hub.py check` (when `vermin` is installed) check every skill script, not only `install.py`, for Python 3.8 compatibility. A test keeps the skill folder lists in `skill-router` and `skill-orchestrator` equal to `AGENTS` in `install.py`. The template is agent-neutral.
- Fixed: `gradle-android`: `gradle_doctor.py fix --apply` and `add-lib --apply` crashed on Python 3.8 and 3.9 (`Path.write_text(newline=)` is 3.10+).
- Updated: `skill-dispatcher` declares `requires: skill-router`; `adb-connect`, `adb-debug` and `adb-device-control` declare `requires: adb-tool`, so installing one of them on its own also installs the skill it runs.
- Updated: `lint-checker` and `robotframework-libraries` mark their guarded Python 3.11 / 3.9 lines for `vermin`; `skillforge` points to `template/SKILL.md.tmpl`.
- Tooling: hooks in `tools/hub.py`. `hook post-edit` rebuilds the generated files after an edit to any of their sources, and is silent unless the build fails or a generated file was edited by hand. `hook stop` runs `check --changed` when an agent is about to finish and, if it fails, blocks once per failing state with the short report (at most 3 times a session; states that passed are not rechecked). `hook pre-commit` verifies without writing. `setup-hooks` installs the git pre-commit hook (never replacing a foreign one) and merges the agent hooks into `.claude/settings.json`, keeping other settings; it is a dry run unless `--yes`, and `--remove` undoes it. `HUB_HOOKS=off` disables all of them.
- Updated: `contribute-skill` uses `hub.py new-skill` and `hub.py check --changed`, keeps the manual steps for older checkouts, and covers the new placeholder errors.
- Tooling: `tools/hub.py`, one command per repository chore with short output. `check` rebuilds the generated files and then runs everything CI runs in parallel (about 14 s instead of about 60 s one after another), printing one line per step group, the output of failed steps only and the command to rerun each; `--changed [REF]` runs only the tests affected by changes. `new-skill` copies `template/`, writes the frontmatter, registers the skill in `marketplace.json` (also creating a new plugin and its `CATEGORY_TITLES` entry) and `examples/prompts.json`, and rebuilds. `validate_skills.py` now rejects leftover `TODO:` placeholders and template text.
- Added: `lint-checker` (new `code-quality-tools` category): lint a project in any language. `lint_check.py` detects languages and the configured or installed linters (ruff, ESLint, Biome, golangci-lint, clippy, RuboCop, ShellCheck and more), runs them in one report with a dry-run-first `--fix`, lints only changed files with `--changed`, and has built-in checks that need no tools (conflict markers, Python/JSON/TOML syntax, leftover debug code, whitespace). Java and Kotlin are linted through the Gradle or Maven build's Checkstyle, PMD, SpotBugs, ktlint, kotlinter, detekt, Spotless and Android Lint tasks, run with the project's wrapper.
- Added: software design skill set (new `software-design-tools` category, `skills/development/software-design`), based on the ideas in *A Philosophy of Software Design* (John Ousterhout) and written in original words: `software-design-guardrails` (always-on design rules; `install_guardrails.py` writes them into a project's agent instruction files, copies the checker into the project and adds a pre-commit hook, as a dry run unless `--yes`; `design_check.py` flags red flags such as pass-through methods and variables, shallow one-use functions, overexposed parameter lists, swallowed and repeated error handlers, duplicated code, comments that repeat code, missing or contaminated interface comments, vague names, generic containers and kludge markers, for Python via `ast` and for C-family languages heuristically, on whole trees or only changed lines (`--diff`, `--staged`), with baselines, inline ignores and JSON output), `deep-modules` (interfaces, information hiding, layers, splitting and merging), `error-handling-design` (define errors out of existence, mask, aggregate, crash), `obvious-code` (comments, names, consistency) and `design-it-twice` (compare designs before coding; `design_note.py` scaffolds and checks the design note; strategic programming; performance).
- Added: context management skill set (new `context-management-tools` category): `context-handoff` (when to checkpoint, compact or restart a long agent session; `handoff.py draft` pre-fills a handoff note from git state and `check` flags missing sections, phrases that rely on lost history, relative dates, missing files and secrets in notes and sub-agent briefs), `context-memory` (durable one-fact-per-file agent memory with an index; `memory_lint.py` lints a memory folder for unindexed or dead entries, duplicates, missing reasons, stale file references, relative dates and secrets, and builds the index), `context-window-budget` (context budgets for LLM apps and agent loops; `context_budget.py` plans a window, analyses where a transcript's tokens go and trims it by truncating or clearing old tool results and dropping whole old turns without splitting tool-call pairs). The bundle also includes `context-engineering`.
- Added: `rest-api-testing` (new `api-testing-tools` category): REST API testing for web applications in any field. It plans cases from an OpenAPI spec (`api_check.py plan`), lints suites for typos, literal secrets, order bugs and unsafe retries (`lint`), and runs JSON suites (`run`) with variables and chaining, cookies, schema/contract checks, retries only for idempotent requests, polling instead of sleeps, `allowed_hosts`, `--read-only`, masked secrets and JUnit/Markdown/JSON reports. References cover test design and the OWASP API Top 10, REST Assured, pytest, Postman/Newman, Karate, Playwright and SuperTest, and checklists for banking, healthcare, e-commerce, insurance, telecom, travel, logistics, government, SaaS and media.
- Added: JUnit skill set (new `junit-tools` category, Java and Kotlin, JUnit 6.1.3): `junit-test-authoring` (setup check and a test-class generator for Java and Kotlin sources), `junit-migration` (audit for JUnit 3/4/5 code, removed JUnit 6 APIs, tests that never run and weak tests, with migration guides), `junit-run-reports` (Gradle/Maven/ConsoleLauncher commands and a summary of JUnit XML and Open Test Reporting results with causes, flaky and slow tests). The bundle also includes `kotlin-unit-test`.
- Added: UI Automator skill set (new `uiautomator-tools` category, Kotlin and Java, androidx.test.uiautomator 2.4.1): `uiautomator-test-authoring` (setup check and generator for tests, page objects, Macrobenchmarks and Baseline Profile generators), `uiautomator-migration` (audit of legacy and flaky code with a migration map), `uiautomator-run-debug` (runs tests with Gradle or `am instrument` and explains failures from raw output or JUnit XML). ## 1.3.0 - 2026-11-16

- Changed: skills moved from `skills/<name>/` to `skills/<area>/<group>/<name>/`, with five areas (`testing`, `development`, `design`, `generic`, `external-tools`) and group subfolders. Skill names, plugin names and install commands are unchanged. `catalog.json` gains `area` and `group` per skill and an `areas` list, and each skill's `path` is its new folder. The installer, validator, catalog builder, both MCP servers, `skill-router` and `skill-orchestrator` find skills at the new depth; the installer still reads older flat releases. The validator rejects skills outside the layout and duplicate names.

- Added: `skill-hub-mcp/`, a new MCP server kept beside `mcp-server/`. It searches (BM25), routes multi-part requests to skills, reads playbooks, detects agents, lists installed skills, and plans installs, updates and removals. With `--allow-install` it can apply a plan the user agreed to, through a one-time token; without it the server is read-only.
- `skill-router`: word forms now share a stem, so "rebase" finds `git-rebasing`; routing hints added for `git-rebasing`, `git-rewriting-history`, `git-undoing-things` and `git-stashing-and-cleaning`.
- `template/`: added `references/details.md`, so the link in the template's `SKILL.md` resolves.
- Added: `context-engineering` (in `ai-efficiency-tools`): one central context file, thin pointers for each tool, layered loading, a token budget and handoff notes, with a script that finds duplicated or drifting instruction files and creates the pointers.
- Added: `ai-token-saver` (new `ai-efficiency-tools` category): audits a project for context waste and lists habits that cut token use and cost.
- Added: `adb-tool`, `adb-connect`, `adb-device-control`, `adb-debug` (new `adb-tools` category).
- Added: `gradle-android` (new `gradle-tools` category).
- Added: `install.bat`, a one-shot Windows installer with precondition checks. It now honours `SKILLHUB_REF` instead of always reading `main`.
- Installer: update detection compares every file of a skill, not only `SKILL.md`, so a change to a bundled script or reference is now reported and `--update` refreshes it. Line endings are ignored.
- Installer: records what it installs in `.skill-hub.json` in each skills folder (skill, hub version, repository); new `--installed` lists the hub skills an agent has, their version and whether they still match the hub.
- Installer: a release download (`--ref v1.3.0`, or the new `SKILLHUB_REF`) uses the release archive and checks it against the release's `SHA256SUMS`; a mismatch stops the install.
- Installer: unit tests in `tools/test_install.py`, run by CI and the release workflow.
- Docs: the `--plugin` table in `GUIDE.md` is generated from the marketplace (it listed 14 of 22 plugins); update, remove and pinning steps corrected; marketplace description is agent-neutral.
- MCP server: removed the `uvx skillhub-mcp` instruction. That PyPI name belongs to an unrelated project; this server has not been published.
- Repo: rules moved into `rule/`; `code-reviewer` agent for skill review.
- Added: `skill-router` (in `hub-tools`): front door for any request. Splits it into parts, grades each basic or advanced, checks the basics are given (file, link, device, tools), and picks the installed skills to load, with editable routing hints and a hand-off to `skill-orchestrator` for multi-skill jobs.

- `skill-orchestrator`: hand-off briefings for inter-skill communication. `run done` records `--fact key=value` and `--question` beside the note and outputs, and the new `run handoff DIR [N]` prints one briefing of everything earlier steps passed on.
